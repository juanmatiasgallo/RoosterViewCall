# Rooster Development System (RDS)

## Purpose

The Rooster Development System (RDS) is the official engineering standard used by RoosterCode.

It defines how features are planned, branched, implemented, reviewed, and merged, so that every project — human or AI assisted — follows the same process.

## Scope

RDS applies to all RoosterCode projects, not only this one. It is designed to be copied as-is into new repositories.

## Documents

- [WORKFLOW.md](WORKFLOW.md) — end-to-end development lifecycle, from roadmap to merge
- [BRANCHING.md](BRANCHING.md) — branch naming and structure conventions
- COMMIT-CONVENTION.md — commit message format
- PULL-REQUEST.md — pull request structure and expectations
- CODE-REVIEW.md — code review guidelines
- AI-WORKFLOW.md — rules for AI-assisted development
- CHECKLISTS.md — definition of done and review checklists

## How to Use This Directory

1. Read `WORKFLOW.md` to understand the full development lifecycle.
2. Read `BRANCHING.md` before creating a branch.
3. Follow the remaining documents as they are added to this directory.

When starting a new RoosterCode project, copy this `docs/development` directory unchanged and adjust only project-specific details (e.g. ticket prefix).
